# T03: T9 layout and touch behavior

Development version: `3.3.13-t9.6-dev`, versionCode `20261107`.
Minimum Android version remains API 21. No native dependency or schema change.

## Layout contract

- Both bundled themes opt in with `t9_layout: true` and share a four-row layout.
- Rows 1-3 contain the 3x3 syllable grid plus a right function column
  (Backspace, Enter, Symbols). The bottom row is Numbers, comma, Space,
  period, literal zero.
- At >=400dp usable width, the pinyin list occupies a left sidebar only if
  at least 300dp remain for the keyboard. Font scaling increases the sidebar
  width; narrow/large-font layouts use a horizontal list above the keys.
- The segment row and pinyin area are reserved while the T9 keyboard is
  selected, including when composition is empty. Candidate contents do not
  control primary-key geometry.
- Left/right one-handed layouts use a 320dp keyboard anchored to the selected
  side. At <=480dp screen height, sufficient width also reserves the pinyin
  sidebar; it sits toward the center of the screen, not between the primary
  keys and the selected hand's edge. Key order is not reversed.
  Custom key height overrides the theme;
  positive values below 48dp are clamped to 48dp. Theme default is 60dp per
  row (50dp in landscape). T9 ignores split-keyboard spacing. The maximum
  height also reserves space for composition controls and system bars.
- The T9 segment strip replaces the duplicate floating preedit while visible.
  This only changes presentation; engine composition/caret data and non-T9
  floating preedit remain intact.
- Width and height preferences are under Settings > Virtual keyboard.
  Existing feedback, long-press delay, slide threshold and slide step settings
  remain in use. Haptic hardware quality needs a physical device.

## Key contract

| Key | Tap | Long press |
| --- | --- | --- |
| Upper-left separator (`|`, hint `1`) | Rime apostrophe delimiter | Literal `1` |
| `ABC` through `WXYZ` | T9 encoding `2` through `9` | Corresponding literal digit |
| Bottom `0` | Literal `0` | No separate action |
| Space | Rime Space, selecting a candidate when composing | No separate action |
| Comma / period | Schema punctuation; no literal digit substitution | No separate action |
| `123` | Numeric keyboard; ASCII digits, not candidate numbers | Chinese/ASCII mode switch |
| Symbols | Symbol keyboard, preserving pending T9 composition (T02) | Schema menu |
| Backspace | T02 editing/unlocking rules | Cancellable repeat |
| Enter | Existing Rime/editor Return path | No separate action |

Literal digit actions go through the serialized Rime API. Pending input is
finished verbatim using the T02 full-input Return path, then the digit is
appended in the same response. This intentionally does not select a numbered
Hanzi candidate. A failed Return leaves the pending composition available
instead of overwriting it. Literal digits are a commit boundary, not an edit
inside a still-composing syllable.

Pinyin marked with `+` in the compact sidebar is a completion, not a complete
syllable. Its accessibility description and tooltip retain the full label.
Unmarked entries and segment locking keep the T01/T02 meanings.

Space uses the existing slide-cursor path. Thresholds/step sizes now use dp
as labeled in settings, carry fractional movement between events, and honor
multi-step movement. A recognized swipe remains a swipe even if the finger
returns to its starting position. Long press, swipe and cancelled touch do
not also execute the ordinary click.

## Regression entry points

- `ThemeGoldenTest`: both shipped YAML files, digit commands, main grid,
  four 100-percent rows, fallback keyboard.
- `T9LayoutPolicyTest`: width/font/hand matrix and >=48dp smallest key.
  Compact landscape also checks sidebar space and the height budget.
- `RimeApiDelegationTest`: generated session delegate implements the new API.
- `T9EditingProbe`: unchanged T02 editor/engine behavioral checks.
- `T9LayoutProbe`, via runner argument `-e t03 true`: real keyboard targets,
  stable positions before/after candidates/locking/clear, both themes and
  both one-handed modes, status/candidate/control bounds, absence of duplicate
  floating preedit, screenshots, literal digits and gesture conflicts.

Run the Android probe separately at 360dp, 412dp, tablet, landscape and
large-font configurations. Restore emulator display overrides after testing.
`run_t03.py --adb /path/to/adb --serial emulator-5560 --output /test/output`
runs that matrix, including short and large-font landscape, and restores
existing display overrides in a `finally` block. `--geometry-only` skips the
repeated gesture/full-pinyin checks while retaining every layout snapshot and
candidate/lock/clear transition. Use full checks on phone and landscape, and
geometry-only checks for additional viewport variants; results record the mode.
Use a separate output directory for each invocation.
It requires the app, matching test APK, app-specific storage and enabled IME
to have already been set up on the emulator.
Only isolated emulator app data may be used; never reset a personal dictionary.
Record APK hashes and viewport settings with results. Passing model tests alone
is not visual acceptance; physical haptics and Android 5.x runtime support are
separate from the API 35 emulator checks.
