## 设计决策

界面使用 `T9StateProto` / `T9SpanProto`，音节来自**当前方案已部署的 prism、主词典音节表和 Rime 音节图**。
不枚举字母组合，不使用候选注释作为协议，也不从前若干个汉字候选猜测可选拼音。

`experiment.cc` 比较了两条路径：

- 原始字母重查：`ni'426` 保留后续数字，得到“你好”及其他 `ni` 开头的候选，不提交文字。
- Rime 插件约束：实验过滤器读取 `Phrase::code()`，能够约束首音节；但过滤已有候选不能保证生成被句子搜索提前淘汰的路径，穷尽候选也增加开销。未把该实验过滤器加入应用。

分词反例证明简单字母重查仍不够严格：`xian'` 同时匹配“先”和“西安”。
因此九键方案增加**原子精确拼写** `~xian~`。结束标记使 `~xi~` 无法成为它的前缀，既排除同码读音，也排除音节内部重新切分。
例如锁定 `ni` 后，引擎输入为 `~ni~426`，用户原始输入仍是 `64426`。这些标记只存在于九键拼写层，界面不显示它们。
重查直接设置 Rime context，不模拟提交键；汉字仍由原 `script_translator`、候选选择、用户词典学习与简繁转换处理。
用户自定义模糊规则若使某个精确编码对应多个音节，该选项会被拒绝，不能伪装成严格锁定。

控制器只对明确启用 `trime/t9` 且支持原子编码的方案工作，不修改 librime 子模块。

## 编辑规则

- 第一行显示原始编码段或已锁定拼音；锁定段带锁图标，当前段使用主题选中色，其余数字段保持原样。未锁定的分段只是导航提示，不代表已经确定读音或分词。
- 点击段会把 Rime 光标移到该段末尾，便于退格修改；在句中选择汉字候选时沿用 Rime 的分段选择。点击预编辑末尾或使用 End 后可重新查看整句候选。
- 第二行提供拼音选项，补全项单独标注。完整匹配与补全可同时存在。
- 横屏时编码段与拼音选项并排放在一行，仍可分别滚动；内置九键提供独立的横屏键盘高度，需要在“虚拟键盘”设置中启用横屏模式（沿用原有设置，不自动改变用户偏好）。
- 点击拼音只锁定该段并重新查询，保留前后编码及其他锁定；点击原有汉字候选才选择汉字。
- 解锁按钮恢复该段原始编码，包括补全前未输入的部分；不会把补全字母写回原始数字。
- 在锁定音节后退格先解除该音节锁定，再次退格删除一个原始输入字符。
- 无锁定时的输入与删除也进入同一撤销记录，最多保留 32 步；删掉最后一个编码后仍能撤销。撤销不跨越汉字选择、上屏、取消组合或编辑器删除边界。
- 组合期间 Ctrl+Z 使用九键编辑记录，即使启用了编辑器撤销快捷键设置也不操作编辑器历史；当前未实现九键重做，组合期间 Ctrl+Y 无动作。
- 有组合时，在组合开头退格、末尾向前删除均不影响编辑器已提交文本；只有组合为空才允许删除编辑器文字。
- 关闭图标和 Escape 是“取消组合”，丢弃组合及其撤销记录，不提交原始数字，也不删除已提交文字。
- 长按退格最多有一个待执行任务；松手、触摸取消、按键禁用或视图移除时取消待执行任务。已经进入引擎的一次操作可能完成，但不继续处理积压的删除。
- 点击预编辑和左右移动使用显示、原始输入、引擎输入之间的位置映射，避免进入隐藏的原子编码内部。
- Android 选区使用 UTF-16 单位，预编辑点击 API 使用 UTF-8 字节位置，两者显式转换。组合内部选区收拢到活动端，因为 Rime 只有一个编辑光标；移到组合末尾也会同步。
- 九键内联显示即使选了“提交预览”也保留可靠的编码/锁定拼音，不把汉字预测当作编码位置映射；全拼、双拼保持各自的内联预览设置。
- 仅切换符号页再返回九键不改变组合；实际插入符号仍沿用方案的标点处理规则。
- 回车提交编码、获取原始输入或组合中切换英文时，返回原始编码，不泄露内部标记；补全项恢复的是补全前的数字。
- 光标在组合中间时，回车仍提交完整输入，不丢弃后续编码；已选择的汉字前缀保留，提交后编辑器光标位于末尾。
- 每个界面动作带快照 revision，已经失效的点击不会应用到新的输入串。

## 原生验收

使用 NDK 编译的小型测试驱动链接现有 `librime_jni.so`，不重新编译整个 Rime。
`fixtures/t9_test.dict.yaml` 显式包含 `ni`、`mi`、`ni hao`、`mi gao`、中间音节替换、分词歧义、多音字与特殊韵母测试词。
测试简化了词典、关闭简繁过滤，不代表发布词典的排序或性能。发布 APK 的 OpenCC 和真实 UI 另测。

```sh
python3 script/t9/run.py \
  --source controller_test.cc \
  --cxx app/.cxx/Debug/BUILD_HASH/arm64-v8a \
  --library /path/to/librime_jni.so \
  --adb /path/to/android-sdk/platform-tools/adb \
  --serial emulator-5554 \
  --double-schema /usr/share/rime-data/double_pinyin.schema.yaml
```

全拼使用仓库部署资源中的 `luna_pinyin.schema.yaml`；双拼使用指定的自然码双拼方案文件，均只替换为小型测试词典，记录完整资源摘要。
`--source experiment.cc` 运行方案比较实验。
生成结果位于 `build/t9/RUN_ID/`，包含驱动输出、引擎错误日志、源文件及库摘要。
控制器验收结束后另起进程验证学习持久化，检查导出的测试词条使用正常拼音，未包含私有标记。

驱动只允许模拟器，在全新的 `/data/local/tmp/trime-t9-RUN_ID/user/` 中操作。
不读取、清空或迁移应用中的个人词库，不清空 AVD。
建议模拟器用 `-read-only -no-snapshot -memory 2048 -cores 2`，Gradle 使用一个 worker、受限 Java 堆，构建与模拟器测试尽量顺序执行。

## APK 验收

升级后先重新部署方案。用户目录若有旧的同名 `luna_pinyin_t9.schema.yaml`，它会覆盖内置资源，需要自行合并 `trime/t9`、speller 原子编码和 preedit 更新；应用不覆盖个人自定义方案。

使用 T00 的 `prepare` / `capture` 冻结 APK 身份后，在 Trime 的测试输入面板验证：

1. 输入 `64426`，拼音区与原汉字候选区同时出现。
2. 选择 `ni` 后编辑器没有提交文字，后续 `426` 仍在；再选择“你好”才上屏。
3. 选择 `mi` 可以得到“米高”；中间音节可重新选择、解锁、撤销。
4. 切换全拼、双拼或英文时，九键拼音区不影响原有输入流程。
5. 横竖屏下检查拼音行、候选行与按键没有重叠，长列表可滚动。

源码引擎测试不能代替 APK/JNI/UI 测试，也不能把模拟器 ARM 转译时间当作手机性能数据。

### T02 自动化

安装同一次构建的 debug APK 与 androidTest APK，并在独立测试模拟器中启用该输入法后执行：

```sh
adb -s emulator-5560 shell am instrument -w -r -e t02 true \
  com.osfans.trime.debug.test/com.osfans.trime.StartupResponsivenessInstrumentation
```

测试需要 API 29 以上的模拟器，仅测试代码使用 `WindowInspector`；应用仍支持 API 21。
探针打开未保存的剪贴板编辑窗口，检查音节点选、锁定边界、撤销、应用选区、符号页往返、汉字单次提交、取消与退格区别，以及排队期间松手的退格取消。结束时恢复内联显示偏好、原方案与英文状态，不保存剪贴板条目。
必须同时检查输出 `passed=true` 和 `INSTRUMENTATION_CODE: -1`，不能只依赖 adb 的退出码。
